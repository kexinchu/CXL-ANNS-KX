# FlashANNS

目标： 我们要做的服务是：**容量在 CXL-SSD 上的可用 ANNS**。Host 打分看起来像数据已经在一小块 DramWindow 里；NAND 不该出现在 **打分指令** 上。

当前做到了：

| 层次 | 状态 | 证据 |
|------|------|------|
| 打分 load | **已 hide** | `from_win=100`，bounce=0 |
| 单 query 等下一跳页 | **未 hide** | 19.8 ms vs oracle 11.4 ms |
| 服务层「像没 flash」 | **未达到** | 50.25 / 85.8 ≈ **0.59×** |

**瓶颈不是带宽。** 有用流量到 oracle 也只要 ~1.02 GB/s，低于单盘软件随机峰 **1.560 GB/s**。缺的是：一条 walk 必须打完 hop *i* 才知道 hop *i+1* 的向量页。

下一刀（设计已写、未实现）：`--spec-beam-nbrs M` —— 点一进 beam 前 M 名就异步预取 N(u) 页，而不是 expand 当下才拉。

---

## 1. 产品合同（不能降）

- Host DRAM **只存稀疏图**（`pagebin_graph.bin`，1.28 GiB）。向量和 expand-bundle 在 NAND。
- DramWindow 是 **cache**，不是第二份索引。现在用 NUMA node 1 的 1 GiB host DRAM 当替身（现场没有 CXL-DRAM / DAX）。
- 全精度分数 100% 来自窗口：`from_win=100`，bounce=0。Hide 失败就修 runtime，**不改 Intro**。
- 协议：T2I-10M，oneshot-fp，**L=400**，k=10，seed=42，recall@10 ≥ 0.92。
- True-cold = `rmmod`+`insmod` 直到 `cache_used=0`。`--flush-window` 不算 true-cold。
- 利用率：**page-touch ≠ 利用率**。正确口径是 `issue_use`（这次 expand 的未见邻居 / 该页上完整 ID）。禁止 `--score-page` 给 sibling 打分刷 100%。
- 占用分母：孤立随机 `PREFETCH_BATCH` **1.560 GB/s**（`/sys/block/<ns>/stat` 扇区）。禁止用 `promote_GBps`。

论文里要写进正文的指针追逐上限：**一次 walk 在 hop *i* 打完分之前，无法完全隐藏 hop *i+1*。** 跨 query 才是把设备 QD 拉满的手段。

## 2. 系统长什么样（对外怎么说）

```
  Host CPU
    ├─ 图（DRAM 文件）     ← 邻居 ID 立刻能读
    ├─ DramWindow 1 GiB    ← 只从这里打分
    └─ ioctl PREFETCH/READ
         └─ vmem_sw（软件 memory-semantic 代理）
              └─ 一块 Dell/Kioxia CD8P 1.92 TB
                   ├─ pagebin @ 420 GiB（向量）
                   └─ expand-bundle @ 460 GiB（每点 N(u) 的 7×4KiB）
```

**对外身份：** FPGA 挂的 NVMe + 软件 memory-semantic 代理。  
**不是：** 产品级 CXL.mem SSD，也不是 24 GB/s 的 CXL-SSD→CXL-DRAM。

Expand-bundle：每个点的 32 邻居占 7 张连续 4 KiB。Expand 只 prefetch **含未见邻居** 的页，只打这些邻居的分。这是 page 管理，不是冗余计算。

## 3. 硬件现场（两套 boot，不要混）

机箱里**确实有 2 块** CD8P。锁定 hide **只绑了其中 1 块**。CXL.mem / 可用 FPGA BAR **没起来**。

### 锁定 hide 行当时（6.18，8/30）

| 项 | 值 |
|----|-----|
| NAND | 当时的 `nvme4n1` = **d9** `2F50A1360XK3` |
| FPGA | Altera `1172:0000` @ `15:00.0`，BAR0 32 GiB；读 `0xff` / 挂 |
| 数据面 | `vmem_sw` 单盘：28 GiB RAM map + 4 GiB cache |
| DAX | **无**。窗口 = `mbind` node 1 |

### 写本文时（7.0.0-30-generic，8/31 下午）

| 项 | 值 |
|----|-----|
| kernel | `7.0.0-30-generic`（不是 6.18） |
| CD8P | **d8** = `/dev/nvme3n1`，**d9** = `/dev/nvme4n1`（块设备名漂了） |
| FPGA `15:00.0` | BittWare `12ba:0075`，BAR0 256 MiB **disabled** |
| `ntcx` / `1172:0000` | **不存在**。不要再 mmap 旧 BAR |
| `vmem_sw` / `nvmex` | **未加载** |
| `/dev/dax*` | 无。`cxl list -M` = `[]` |

**事故：** 有人在 6.18 上装过树外双盘 `vmem_sw`（逻辑 3.58 TB，2 MiB 条带）。420/460 GiB 布局被打散。双盘模块 **禁止** 再装回当前单盘镜像。

**禁止对外发的数：** `vmem.ko` / BAR `0xff`、把 node 1 说成 CXL-DRAM、24 GB/s。

## 4. 主结果（claim 用这两行，不改）

协议：单路、1 GiB 窗口、expand-bundle、ebatch=8、ahead=2、look=0、`--no-score-page`、true-cold。

### 4.1 Oracle（同 query，nq=20，L=400）

| 行 | QPS | mean | recall@10 | NAND |
|----|----:|-----:|----------:|------|
| Oracle host DRAM（9.6 GiB populate） | 66.52 | 14.8 ms | 0.950 | 0 |
| **Oracle 1 GiB 窗口**（WS 已 pin，`freeze_fills`） | **85.78** | **11.4 ms** | 0.925 | **0** |

**旧行 VOID（FPGA 三角色架构）：** 85.8 仍是历史 node1 / `vmem_sw` 数，**不是**本架构（BAR=CXL-DRAM、双盘=CXL-SSD、Host 2 GiB searcher）的 Oracle。表不删。

85.8 / 11.4 是「hide 完全成功」的 **单路** 上界（旧 node1 路径），不是 4 路服务上界。  
不要和 L=250 oracle 169 QPS 比（recall 协议不同）。

### 4.2 Hide 锁定

| nq | QPS | mean | recall | from_win | occ | 相对 oracle |
|---:|----:|-----:|-------:|---------:|----:|-------------|
| **20** | **50.25** | **19.8 ms** | **0.940** | 100 | 38.5% | **0.59×**，+8.4 ms |
| **100** | **49.25** | **20.3 ms** | **0.933** | 100 | 36.0% | 同量级 |

nq=20 细项：hit 13.75%，`overlap=0.07`，`crit_wait` **1.24 ms/q**，有用 ~12 MB/q。

替换 50.25 / 49.25 的条件：T=1 nq=20 **且** nq=100 在 iso-recall 上同时赢。

### 4.3 多路（服务吞吐，不能和 85.8 单路比）

每线程私有 512 MiB 窗口：

| T | nq | QPS | mean | occ |
|--:|---:|----:|-----:|----:|
| 1 | 20 | 50.25 | 19.8 ms | 38.5% |
| 4 | 20 | **79.02** | **34.4 ms** | 62.1% |
| 4 | 100 | 87.21 | 29.3 ms | 65.8% |
| 8 | 100 | 69.14 | 75.5 ms | 过订阅，VOID |

公平 T=4 shard oracle：**136.23 QPS / 15.8 ms / 0.930**。  
**旧行 VOID（FPGA 三角色架构）：** 136.23 同样是历史 node1 / `vmem_sw` 四路 shard 数，**不是**本架构的 Oracle。表不删。  
`4×85.8=343` **是错的**。T=4 hide / oracle ≈ **0.58×**，和单路同一缺口。

T=4 另有一层字节墙：默认路径 `cap_qps` **121–127 < 136**。即使占用拉满 1.560，也顶不到四路 oracle。

## 5. 瓶颈拆解（组会核心）

### 5.1 不是带宽

```
有用 ≈ 12 MB / query
T=1 到 85.8：12 MB × 85.8 ≈ 1.02 GB/s  <  1.560 GB/s
```

单路占用 38.5% 是因为 **算完才知道下一跳、管线几乎不重叠**（`overlap=0.07`），不是盘已经打满。把占用刷到 100% **不能**当 T=1 的赢。

1.560 是什么：true-cold、4K 随机、`vmem_sw` ioctl、**一块**盘、`stat` 扇区。  
1.560 不是：CXL.mem、FPGA DMA、双盘之和、24 GB/s。

### 5.2 是数据依赖

图在 host：邻居 **ID** 立刻能读。缺的是这些 ID 的 **800 B 向量页**（在 NAND）。

```
expand u  →  打分 N(u)  →  才知道下一跳 v  →  才发 N(v) 的页
                 ↑
            临界路径锁在这里
```

+8.4 ms 粗拆（nq=20）：

| 部分 | 时间 | 占比 |
|------|-----:|-----:|
| `crit_wait`（frontier 空，显式等 NAND） | 1.24 ms | 15% |
| 串行 hop + install memcpy + stall | ~7.2 ms | 85% |

打分指令不读 SSD；**query 仍在临界路径上等 SSD 把页装进窗口**。四路 79 QPS 只是让盘在别人的 query 上保持 QD，单 query 不会变成 11.4 ms。

### 5.3 利用率也还没到故事里的 100%

`slot_use=100` **虚高**（「本 query 是否打过该 ID」）。真口径：

```
issue_use = 64.30%     （发出的页上，只有 64% 是本跳未见邻居）
byte_use  = 60.76%
```

入度重排 N(u) 已整盘打完并复测：**issue_use 64.3 → 63.0，没有修。** 全局入度 ≠ 本 query 已访问集合。claim 仍用原图序 bundle。

## 6. 爬坡与失败刀（避免组里建议重跑）

### 6.1 单路怎么从 ~3 QPS 到 50

| 阶段 | nq=20 QPS | 备注 |
|------|----------:|------|
| 同步 ioctl（搜索线程上打 NAND） | 2.8–7.8 | 起点 |
| clock alloc + miss-only | ~23 | 不再扫 256k 帧 |
| stall 满管线 | ~31 | 不再丢 miss |
| expand-bundle ebatch=8 ahead=2 | **50.25** | 锁定 |

PipeANN 式管线目前 **只有** async fill + ebatch=8/ahead=2。`pick_batch` 仍是严格 best-first。

### 6.2 不要当赢再跑

| 刀 | 结果 | 为什么废 |
|----|------|----------|
| `--score-page`（含 AVX2） | 21 QPS，「利用率 100%」 | 冗余打 sibling，禁止当故事 |
| `--lookahead-k 8` | 31 QPS | 猜的 8 个不是下一波 expand |
| ebatch 16/32、ahead=3（T=1 默认） | ≤46 | T=1 加宽 batch 更慢 |
| `--min-issue-use` | 失败 | 跳低产页回到随机 pagebin |
| 入度 bundle | issue_use 不涨 | 见 §5.3 |
| 共享 1 GiB × 4 线程 | 50.7 QPS / 70 ms | 窗口锁 |
| `pipe_w=32` / slim warm / score thread | 掉或崩 | 撤回 |
| `--cont-batch` 原实现 | SIGSEGV | 不要复用 |
| T=8 | 69 QPS | 过订阅 |
| 占用刷到 100% | — | T=1 不是带宽墙 |
| `vmem.ko` / BAR 数 | — | 不是 CXL.mem BW |

和 PipeANN 论文行（57.6 QPS @ L=2000、PQ on）比，是 oneshot FP vs PQ navigation，**不是** 藏起来的 bar。残差写成对 oracle 的 gap。

## 8. 下一步（建议顺序）

```
① 恢复单盘 hide（d9 / nvme4n1）→ 复基线约 50 / 20 ms
② 实现 --spec-beam-nbrs M（默认 0，claim 路径不变）
③ 扫 M ∈ {8, 16, 32}；64 仅当前三档 crit_wait 仍高再加
④ 仅 T=4 打开更大 QD（ahead=3 / ebatch=16），T=1 默认保持 8/2
⑤ 双盘 restage / HPS：批准后再动；HPS 这轮停放
```

### Approach A 在干什么

现在：expand `u` 才拉 N(u) 向量（best-first 锁）。  
之后：`u` 插入 cand 且排进前 **M** 名，就异步 `issue` N(u) 的 bundle 页（`stall_if_full=false`）。下一波 `pick_batch` 选中 `u` 时，页应已在飞或已在窗。

和 look=8 的差别：集合跟 **beam 成员** 走，不跟「本跳猜的 8 个」走；不每 hop 全量刷新。  
浪费：进 cand 后又被 evict、从未 expand 的点。M 砍这个尾巴。  
**不**对预取页上的 sibling 打分。

期望：吃掉部分 `crit_wait` + 一部分串行 hop，**2–4 ms 量级**，不是直接到 11.4。  
验收：nq=20 与 nq=100 的 mean 都低于复基线；`from_win=100`；recall≥0.92；QPS 不低于复基线 −2%。`crit_wait` 应下降。若只涨字节、mean 不降 → 整刀撤回。

**不做第一刀：** 放宽 expand（slack best-first / 更大 ebatch）—— T=1 上已失败。加厚 2-hop warm 只能盖开头，L=400 后程仍 miss。

## 9. 论文怎么写残差（避免组里误读）

建议叙事：

> 打分路径已经看不见 flash（`from_win=100`）。单 query 相对窗口 oracle 仍是 0.59×，因为 best-first 图走步在 hop *i* 分数出来之前不能发行 hop *i+1* 的向量页。这是指针追逐，不是「search 看见了 flash」，也不是设备带宽不够。

不要写：

- hide 已经等于 oracle；
- 四路 79 QPS 证明单路 hide 成功；
- 占用 38% 所以下一优先是把盘打满；
- 当前路径测到了 CXL.mem / 24 GB/s。
