# 冻结预取器：论文用实现说明

**状态：已冻结，禁止再改实现。** 合同与数字见 `2026-09-04-prefetcher-freeze.md`。下文可直接改写入论文设计节。汉字约八百。

面向 CXL-SSD 的 best-first 图搜索有一个硬信息依赖：不算出当前点邻居的全精度分数，就无法决定下一跳该扩谁。若每一步都把邻居向量从 NAND 拉上来打分，查询会被串行随机读绑死。我们在 T2I-10M 上测过这条 oneshot 全精度 hop 路径：每查询约二十二兆字节 NAND，hide 相对主机 oracle 只有零点二倍。冻结预取器的核心，是把「该扩谁」从设备上的全精度向量挪到主机内存里的近似排序，再把设备读收成查询末尾的一次提交。

实现分四段。第一段用一万点导航图走到入口。邻接表放在主机图文件里，展开邻居不会踩 CXL-SSD 的映射缺页。第二段在主机上用六十四字节乘积量化做非对称距离计算：查询先编一张分块查找表，每个候选只读六十四字节码字并累加近似内积，把候选集维持在四百。这一阶段零设备读。码本按搜索编号重排，与页槽位映射对齐。第三段只对这四百个候选的向量页发一波 HidePipe：收集未驻留的四千字节页，若页号跨度不超过三十二且密度过半则补成连续 extent，经 bounce 缓冲拷进两吉字节主机窗口，等到覆盖后再做全精度最大内积重排，交出前十。打分必须发生在窗口命中之后，禁止在 bounce 上算距离。第四段是页布局：用查询共建的共现与 extent 图，把仍会一起打分的向量尽量放进相邻四千字节页，镜像落在一千一百吉字节偏移，搜索时带槽位映射。软件页缓存锁在一百兆字节，每次评测先污染四百二十吉字节，因此吞吐来自「束搜索不再读盘、最后一波重排」，不是跨查询复用。

我们明确放弃了中途按 hop 宽度预取、按页打分、投机邻居，以及在束内提前发页的 pipe-drive。后者会多发空页、打浅真正的末批队列，吞吐反而下降。六十四字节码比三十二字节必要：后者召回掉到零点七四。冻结数字是单线程、束宽四百、返回十、污染后：二十查询 hide 一百十点九四 QPS、召回零点九二五、相对 oracle 零点六九倍；一百查询 hide 一百十六点二九 QPS、召回零点九二三、相对 oracle 零点七二倍。预取器的身份是「信息在量化码、字节在最后一波」。实现已锁定，不再改旗标、码本或镜像。
