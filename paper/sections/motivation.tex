\section{Motivation}
\label{sec:motivation}

Section~\ref{sec:background} defined the walk and the fill.
This section measures what happens if that fill is treated as a slightly
slow DRAM load or as a DiskANN sector read.
Each measurement asks two questions: does the effect exist, and what
throughput or NAND-traffic penalty does it cause?
The three results are the constraints Intro named C1--C3
(Table~\ref{tab:findings}).

\subsection{The miss cliff}
\label{sec:mot-cliff}

A host \texttt{load} of one vector from CXL-DRAM is a few hundred
nanoseconds.
A matched-size CXL-SSD window-miss read is a NAND fill
(Figure~\ref{fig:mot-cliff}).
On Text2Image-10M ($800$\,B) the $p_{50}$ is $0.28\,\mu$s versus
$89\,\mu$s ($\sim$320$\times$).
On a 10M-item LAION slice ($2048$\,B) it is $0.67\,\mu$s versus
$89\,\mu$s ($\sim$130$\times$).
The miss is a 4\,KB fill, so record size barely moves it; the
CXL-DRAM hit scales with bytes.

A graph walk can pay that tax across hops and newly scored neighbors.
Once a modest fraction of scores miss, wall-clock time is in the NAND
path, not in distance arithmetic.
DiskANN already knew the cliff for block I/O.
The relevant distinction is that a memory-semantic interface does not remove it:
\texttt{load}/\texttt{store} only changes \emph{how} a miss is issued
(\S\ref{sec:mot-qd}).
Treating CXL-SSD as memory-mapped DRAM therefore makes search miss-bound.
The runtime contract that follows is not ``make NAND faster''; it is
that the scoring instruction must not wait on a fill.

\subsection{Prefetch must be wise}
\label{sec:mot-page}

Neighbor IDs are not sequential in the address space, so the next
vector page is not the next byte.
Coalescing four 4\,KB pages into one 16\,KB admission unit therefore
brings siblings the walk will not score.
On a high-dimensional corpus where a record already fills most of a
page, per-record admission versus page admission splits QPS by
$\sim$3.6$\times$ and NAND reads by $\sim$3.7$\times$
(Figure~\ref{fig:mot-pathology}a).
At small dimensions several records share a page and the gap
narrows; page-cache thinking is still the wrong default here.

\label{sec:mot-pref}
Synchronous two-hop prefetch rooted at the top-1, top-2, or top-8
frontier candidates does
not fix the cliff.
Hit rate is almost unchanged, NAND reads multiply, and QPS drops by
$\sim$4--5$\times$ at the widest setting
(Figure~\ref{fig:mot-pathology}b).
Precision (\emph{used$/$promoted}) falls as coverage grows; leftover
pages evict useful ones from a small window.
Wrong pages cost more than a missed page.
A page can be necessary yet still waste most of its vector slots.
The useful policy therefore delays full-precision movement until the
approximate search commits its rerank set, then fetches only that payload
and packs co-used vectors together---not ``prefetch harder.''

\label{sec:mot-beam}
Widening $L$ can become another form of unwise coverage.
Under the fixed hop budget, recall and NAND reads both plateau from
$L{=}32$ to 64.
Extra width buys no measured quality benefit in that interval;
quality and I/O cost must therefore be reported together.

\subsection{One query cannot fill the device}
\label{sec:mot-qd}

Best-first search is pointer-chasing: hop $i$ must score before the
walk knows which vector pages hop $i{+}1$ needs.
A single query therefore leaves device-queue bubbles---the beam
fill stream ramps slowly, the next fill is unknown, and the walk drains at the
end (Figure~\ref{fig:mot-bubbles}).
A block interface exposes I/O requests that a scheduler can interleave
across independent queries.
On CXL-SSD the programming model is a faulting address space.
A blocking \texttt{load}/\texttt{store} (or a blocking
\texttt{memcpy} from the mapping) is a synchronous NAND fault:
effective queue depth collapses to $\approx 1$ per thread.
If a query waits for those fills before scoring, NAND latency remains
on its critical path.

The idle device is a pipeline problem, not a bandwidth wall.
Continuous issue across queries is what can hold depth; it does
not, by itself, make one walk as fast as an in-window oracle, and
it does not change which nodes the walk visits.
The implementation of that issue belongs in~\S\ref{sec:design}.

\subsection{From measurements to constraints}
\label{sec:mot-map}

Table~\ref{tab:findings} is the contract for~\S\ref{sec:design}.
We do not treat CXL-SSD as uniform memory (C1): scoring must not
touch NAND.
Prefetch must be wise (C2): trigger at candidate commitment, fetch only
the committed full-precision payload, and place co-used vectors so each
page carries more data that reranking consumes.
One walk cannot fill the device (C3): issue must be asynchronous and
cross-query so pointer-chasing bubbles do not collapse queue
depth.\footnote{A small shared pin of entry vertices helps a narrow
beam more than deepening one walk. That is an admission hint, not a
positive LFU-hot-set module, and not a fourth challenge.}
Placement of neighbor IDs in host DRAM is a premise for C2, not a
separate challenge: without it the prefetcher misses once just to
learn whom to fetch.
