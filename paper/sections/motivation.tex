\section{Motivation}
\label{sec:motivation}

Section~\ref{sec:background} defined the walk and the fill.
We now isolate the three effects that make a Flash-backed, memory-semantic
path different from either DRAM or a conventional DiskANN sector path.
In our prototype, host DRAM holds graph adjacency, PQ-64 codes, query state,
and a bounded scoring window. Full-precision vectors reside in the
\texttt{/dev/vmem0} address space, whose fixed 4\,GiB DRAM cache fronts two
1.92\,TB NVMe backings. Residency, faults, and fills are managed at 4\,KiB;
the 2\,MiB value in the device configuration is only the backing stripe.
An ordinary access blocks if its page is absent, whereas the batch interface
can install requested pages before scoring consumes them.
Each measurement asks two questions: does the effect exist, and what
latency, NAND-traffic, or device-utilization penalty does it cause?
The three results are the constraints Intro named C1--C3
(Table~\ref{tab:findings}).

\subsection{The miss cliff}
\label{sec:mot-cliff}

Figure~\ref{fig:mot-cliff} measures the three paths using 2,000 deterministic,
distinct vector pages per repetition on all three 10M-item datasets.
The host path is a prefaulted buffer; the CXL-cache path drops the process PTE
but retains the VMEM page and incurs no physical read; the Flash path begins
with the page absent and must perform a 4\,KiB fill. Median host access is
$0.031$--$0.101\,\mu$s, a resident CXL-cache access through the software
memory-semantic path is $3.97$--$7.39\,\mu$s, and a Flash fill is
$81.0$--$83.2\,\mu$s. Thus a fill is another $11.3$--$20.4\times$ over an
already resident VMEM access and $804$--$2{,}682\times$ over the host window.
The narrow $81$--$83\,\mu$s fill range across datasets is consistent with a
page-granular miss rather than vector arithmetic.

A graph walk can pay that tax across hops and newly scored neighbors.
Once a modest fraction of scores miss, wall-clock time is in the NAND
path, not in distance arithmetic.
DiskANN already knew the cliff for block I/O.
The relevant distinction is that a memory-semantic interface does not remove it:
\texttt{load}/\texttt{store} only changes \emph{how} a miss is issued
(\S\ref{sec:mot-qd}).
Treating CXL-SSD as memory-mapped DRAM therefore makes search miss-bound.
The runtime contract that follows is not ``make NAND faster''; it is
that the scoring instruction must not wait on a fill.

\subsection{Prefetch must be wise}
\label{sec:mot-page}

Neighbor IDs are not sequential in the address space, so the next
vector page is not the next byte.
We freeze the PQ-navigation trace of 10,000 LAION-10M queries at
$L{=}400$ (recall@10${=}0.9131$), so every policy receives exactly the
same committed rerank set. Selective 4\,KiB admission reads
$0.91$\,MiB/query and materializes the set in $2.50$\,ms.
Blindly coalescing each request with the next three address-contiguous pages
raises those costs to $3.97$\,MiB/query and $7.94$\,ms---$4.36\times$ the
physical traffic and $3.17\times$ the latency---while only 28.6\% of admitted
pages contain a vector that reranking consumes
(Figure~\ref{fig:mot-pathology}a). Address proximity is therefore a poor
proxy for graph-search utility.

\label{sec:mot-pref}
Fetching earlier but without selectivity does not fix the cliff.
We expand two hops from the top-1, top-2, or top-8 pre-commit candidates,
union the resulting pages with the same committed set, and replay each policy
from a cold cache. Relative to demand materialization, Top-1 already reads
$3.60\times$ more NAND and takes $3.09\times$ longer. At Top-8, traffic grows
from $0.91$ to $12.07$\,MiB/query, mean materialization latency from $2.51$ to
$28.91$\,ms, and useful-page coverage falls from 100\% to 10.8\%
(Figure~\ref{fig:mot-pathology}b). Recall and the committed useful set remain
identical; the added work is entirely speculative. Wrong pages can therefore
cost more than waiting to identify the right page.
A page can be necessary yet still waste most of its vector slots.
The useful policy therefore delays full-precision movement until the
approximate search commits its rerank set, then fetches only that payload
and packs co-used vectors together---not ``prefetch harder.''

\subsection{One query cannot fill the device}
\label{sec:mot-qd}

Best-first search is pointer-chasing: hop $i$ must score before the
walk knows which vector pages hop $i{+}1$ needs. We first calibrate the same
read-only VMEM path with independent, nonrepeating pages. It reaches 90\% of
its maximum stable read bandwidth only at issued concurrency 128; we call
this measured point the device concurrency knee. We then run the frozen Wise
Prefetcher on each dataset while sampling both backings every 100\,ms,
retaining idle intervals (Figure~\ref{fig:mot-bubbles}).
A block interface exposes I/O requests that a scheduler can interleave
across independent queries.
On CXL-SSD the programming model is a faulting address space.
A blocking \texttt{load}/\texttt{store} (or a blocking
\texttt{memcpy} from the mapping) is a synchronous NAND fault. At $T{=}1$,
the time-averaged effective queue depth is only 0.81--1.49 across the three
datasets. Raising concurrency to $T{=}16$ improves it to 3.23--5.21, yet this
is still at most 4.1\% of the device knee. The limitation is not a claim about
raw NAND channels: it is the concurrency exposed by dependent walks through
this memory-semantic software path.

The large gap between workload QD and the independently measured knee makes
the idle device a pipeline problem, not evidence that the path has exhausted
bandwidth. Continuous issue across queries is what can raise useful depth; it
does not, by itself, make one walk as fast as an in-window oracle, and it does
not change which nodes the walk visits.
The implementation of that issue belongs in~\S\ref{sec:design}.

\subsection{From measurements to constraints}
\label{sec:mot-map}

Table~\ref{tab:findings} is the contract for~\S\ref{sec:design}.
We do not treat CXL-SSD as uniform memory (C1): scoring must not
touch NAND.
Prefetch must be wise (C2): trigger at candidate commitment, fetch only
the committed full-precision payload, and place co-used vectors so each
page carries more data that reranking consumes.
One walk cannot fill the device (C3): issue must be asynchronous and
cross-query so pointer-chasing bubbles do not collapse queue
depth.\footnote{A small shared pin of entry vertices helps a narrow
beam more than deepening one walk. That is an admission hint, not a
positive LFU-hot-set module, and not a fourth challenge.}
Placement of neighbor IDs in host DRAM is a premise for C2, not a
separate challenge: without it the prefetcher misses once just to
learn whom to fetch.
