\section{Background}
\label{sec:background}

\subsection{Graph ANNS walk}
\label{sec:bg-anns}

A graph ANNS index (Vamana~\cite{diskann}, HNSW~\cite{hnsw}) stores, for
each vector, a neighbor list of degree $R$. Search keeps a candidate set
of width $L$ (beam / \texttt{efSearch}). A \emph{hop} expands the closest
unread candidate $u$: the walk reads $N(u)$, scores those neighbors, and
inserts the best unseen IDs back into the candidate set. The query
returns the top-$k$ after a hop or candidate budget is spent.

One expand touches two kinds of bytes. Neighbor \emph{IDs} are small
and can live in host DRAM. Neighbor \emph{vectors} are large: on
Text2Image-10M each is 800\,B, so scoring $N(u)$ moves about
$R\times 800$\,B if every neighbor is new. A typical hop is:

\begin{enumerate}
  \item pick the closest unread candidate $u$ from the beam;
  \item read $N(u)$ (IDs only);
  \item score the unseen neighbors' full-precision vectors;
  \item insert the best new IDs into the candidate set.
\end{enumerate}

Two facts follow for a memory hierarchy. First, the walk is
\emph{pointer-chasing}: step 3 of hop $i$ decides which vector pages
hop $i{+}1$ will need. Second, IDs need not live with vectors---the
adjacency list can sit in host DRAM while embeddings sit on a slower
tier. Quality rises with how many useful neighbors are scored; stall
rises with how many of those scores miss the fast tier. Widening $L$
scores more nodes and cools the working set; that coupling is a
measurement in~\S\ref{sec:motivation}, not a claim here.

\subsection{The block-SSD serving stack}
\label{sec:bg-block}

DiskANN~\cite{diskann,freshdiskann} is the reference block-SSD design.
Full-precision vectors and adjacency share 4\,KB-aligned NVMe sectors.
A compact PQ codebook in DRAM ranks neighbors without a NAND read; an
\texttt{aio} beam issues several sector reads at once; a static node
cache pins entry vertices. PQ navigation exists to \emph{avoid}
full-precision reads, not to make NAND faster. Asynchronous I/O
\emph{hides} remaining reads by overlapping them with other work.
Because graph and vectors share a sector, one 4\,KB read is bound to
whatever else the layout packed into that page.

PipeANN~\cite{pipeann} keeps that layout, overlaps compute with I/O
inside one query, and can interleave queries to hold device queue
depth. That interleaving is continuous batching \emph{on a block
device}: the first-class objects are the I/O queue and the sector.
The same idea will reappear on CXL-SSD as fetch-level
issue~(\S\ref{sec:design}), against a faulting address space rather
than \texttt{aio}.

\subsection{CXL-DRAM ANNS}
\label{sec:bg-cxl-dram}

CXL.mem maps device HDM into the host physical address
space~\cite{cxl30}. Published Type-3 CXL-DRAM latencies sit in the
140--410\,ns range. CXL-ANNS~\cite{cxlanns,cxlanns-tocs} places the
graph and embeddings in a CXL-DRAM pool and hides that far-memory
delay with a relationship-aware cache and DSA-assisted prefetch.
Cosmos~\cite{cosmos} further offloads traversal and distance to
device-side compute. Second-tier and residual
designs~\cite{secondtier,fatrq,hm-ann} likewise assume a DRAM- or
NVM-priced far tier.

The interface is \texttt{load}/\texttt{store}; the capacity assumption
is that $D$ fits in CXL-DRAM. A service on that line is already
usable in the sense that search never waits on flash. Prefetch and
cache policies tuned for hundreds of nanoseconds do not transfer to a
NAND fill of tens of microseconds. We keep the detailed contrast
in~\S\ref{sec:related}.

\subsection{Flash-backed CXL memory}
\label{sec:bg-cxl-ssd}

A CXL-SSD pairs NAND capacity with a modest DRAM cache and presents a
byte-addressable window~\cite{skybyte,fromblocktobyte,cmm-h}.
Figure~\ref{fig:intro-position}c is the deployment we serve. A
\emph{score-window hit} is a DRAM-class copy. A \emph{miss} is a NAND
fill into that window, then a retry. The programming model looks like
memory; the miss tax looks like flash. Table~\ref{tab:bg-latency}
places the three published tiers next to the NAND fill this paper
must hide. The measured cliff belongs in~\S\ref{sec:motivation}; the
table only fixes the orders of magnitude.

\begin{table}[t]
  \caption{Latency tiers that a graph walk can see.
    CXL-DRAM is the published range; NAND fill is the order on the
    path we measure. The cliff itself is~\S\ref{sec:motivation}.}
  \label{tab:bg-latency}
  \small
  \begin{tabular}{@{}lll@{}}
    \toprule
    Access & Order of magnitude & Where \\
    \midrule
    Host DRAM load & $\sim$80--120\,ns & graph / PQ, if placed there \\
    Score-window hit & DRAM-class copy & resident full-precision bytes \\
    CXL-DRAM (literature) & $\sim$140--410\,ns & CXL-ANNS / Cosmos pool \\
    NAND fill (this path) & $\sim$20--80\,$\mu$s & window miss $\rightarrow$ flash \\
    \bottomrule
  \end{tabular}
\end{table}

The window is bounded, and the admission unit is a page. On
Text2Image-10M a vector is 800\,B, so a 4\,KB page holds several
records---or several unused siblings. A blocking
\texttt{load}/\texttt{store} miss and an explicit prefetch ioctl are
both fills; they differ in \emph{who waits}. If the scoring thread
issues the fill, NAND is on the critical path. If a prefetcher issues
it before the hop scores, the fill can leave that path. That split is
the runtime contract in~\S\ref{sec:design}, not a result.

The prototype we measure is a software memory-semantic node
(\texttt{vmem\_sw}) in front of NVMe, with the score window implemented
as host DRAM (\texttt{mbind}). It preserves fill semantics (a miss
moves NAND bytes into the window). It does not preserve a product
CXL.mem device latency or a CXL-DRAM DAX region. Hardware and generic
OS work on this tier does not manage graph-ANNS residency; those
systems belong in~\S\ref{sec:related}. Implementation limits belong
in~\S\ref{sec:impl}.
Direct-attach CXL-SSD already gives one host flash-priced memory
semantics; that is the deployment we measure. Multi-host one-copy
under CXL~3.x Shared FAM is a premise we do not evaluate.
