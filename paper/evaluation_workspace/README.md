# FlashANNS Evaluation figure workspace

This directory is a compact, editable handoff for the Evaluation figures. It
contains the complete eight-figure paper contract, including the
original-layout Demand control on all three datasets.

## What is complete

The original six figures are reproducible from `data/current-six-figures.csv`.
That aggregate contains 128 marks backed by 640 unique accepted runs (five
runs per mark); every referenced run is present under the authoritative
accepted-evidence root. The corresponding provenance map is
`data/current-six-figures.provenance.json`.

| Figure | PDF and PNG | Data used |
|---|---|---|
| T2I frontier | `figures/current/frontier-t2i.*` | q2, T2I |
| YFCC frontier | `figures/current/frontier-yfcc.*` | q2, YFCC |
| LAION frontier | `figures/current/frontier-laion.*` | q2, LAION |
| Wise Prefetcher | `figures/current/wise-ablation.*` | q3_t1, T2I; physical NAND counters |
| Continuous batching | `figures/current/batching-ablation.*` | q3_t8, all datasets |
| Hide / robustness | `figures/current/hide-robustness.*` | q4_hide, q4_cold_warm, q4_cache |
| Open-loop tail latency | `figures/supplemental/load-tail-latency.*` | q3_load, all datasets |
| Prefetch I/O efficiency | `figures/supplemental/prefetch-io-efficiency.*` | T2I layout and q3_t1 controls |

`data/figure-status.csv` gives the row/run counts and remaining gaps in a form
that can be opened directly in a spreadsheet.

### Supplemental evidence and metric semantics

`data/supplemental-two-figures.csv` contains 45 open-loop load marks and five
I/O-control marks, backed by 250 unique accepted runs. The exact run list is in
`data/supplemental-two-figures.provenance.json`; the audit outcome and metric
definitions are in `data/supplemental-two-figures.quality-report.json`.

The load data is curated rather than mixed: T2I uses campaign `68c6`, while
YFCC and LAION use `4ad7-c3ef`; each dataset/system/rate mark has repeats 0--4.
T2I PipeANN uses its recall-matched `L=2400`, while the internal systems use
`L=400`.

The frozen `extent_use_pct` and `scored_vec_B` counters are zero and are not
used. Host-window requests are not called NAND misses. Physical traffic uses
`nand_read_bytes` and `nand_read_commands`; read amplification is physical
NAND bytes divided by `slots_scored * dimension * element_bytes`. The updated
Wise figure likewise uses physical NAND commands/bytes rather than the invalid
extent counter. In the current aggregate, the legacy
`nand_mib_per_query` alias is also derived from physical `nand_read_bytes`.

## Original-layout Demand frontier

The current aggregate includes 18 original-layout Demand marks: six $L$
values on each of T2I-10M, YFCC-10M, and LAION-10M. Each mark has five accepted
10,000-query repetitions, for 90 runs total. Consequently all three frontier
PDFs are four-system figures and isolate graph/vector extent placement from
prefetching and continuous batching.

The older `t2i-original-layout.*`, `original-layout-complete-marks.*`,
`original-layout-incomplete-runs.csv`, and partial-preview directories are
retained only as historical campaign snapshots. They are not manuscript input
and are not regenerated by the current workflow.

## Reproduce and edit

Edit `scripts/plot_six_figures.py` or `scripts/supplemental_figures.py`, then run:

```bash
./regenerate.sh
```

The copied plotters regenerate from bundled aggregate CSVs and do not access
raw devices. Their regression tests remain in the
evaluation worktree and must be run from that checkout:

```bash
cd /root/chukexin/CXL-ANNS-KX/.worktrees/eval-flashanns-10m
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 \
python3 -m unittest experiments.eval.flashanns.tests.test_plots \
    experiments.eval.flashanns.tests.test_supplemental_figures
```

The script fixes BLAS to one thread because this host uses strict overcommit
and NumPy's default 64-thread initialization can fail even when physical RAM
is available. It regenerates vector PDFs and inspection PNGs without touching
the raw runs.
